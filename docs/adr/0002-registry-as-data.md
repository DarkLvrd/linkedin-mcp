# ADR-0002: Selector and endpoint registry as data, with a runtime overlay

LinkedIn's GraphQL query-id hashes rotate on deploys and its DOM changes monthly; the bridge broke when selectors drifted and needed a manual patch inside `node_modules` (a redeploy). We decided the server keeps its **selector and endpoint registry as versioned JSON data** shipped inside the package, plus a **runtime overlay file** that the server hot-reloads — so a fix lands without a redeploy. When a lookup fails, the server captures a failure artifact (screenshot + DOM dump + which strategies failed) and writes candidate selector suggestions from auto-diagnosis; a human or the agent applies them to the overlay via an `update registry` tool. The multi-strategy lookup order is fixed: aria-label → role → data-test → visible text → structural. Rejected: selectors hard-coded in code (redeploy per break), and a remote registry fetch (adds a server and a privacy surface for what is otherwise a local personal tool).
